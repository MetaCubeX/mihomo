# mihomo 架构与源码阅读指南

## 简介

mihomo 是一个基于 Pydantic 的 Python 库，用于解析来自 Mihomo API 的《崩坏：星穹铁道》(Honkai: Star Rail) 玩家数据。它将 API 返回的 JSON 包装成带类型标注的数据模型，方便在 Python 中以面向对象的方式访问。

本指南面向第一次阅读项目源码的贡献者，帮助你快速建立对整体结构的认识，并给出推荐的阅读顺序。

## 技术栈

- Python >= 3.10
- aiohttp (3.x)：用于发起异步 HTTP 请求
- pydantic (1.x)：用于定义数据模型与数据校验

## 整体架构

项目大致分为三层：

1. 客户端层 (Client)：负责与 Mihomo API 通信，发送请求并接收原始 JSON。
2. 模型层 (Models)：使用 Pydantic 模型描述返回数据的结构，提供类型安全的访问方式。
3. 工具层 (Tools)：提供辅助函数，例如资源地址补全、数据格式整理等。

数据流向：

```
调用方 -> 客户端发起异步请求 -> Mihomo API 返回 JSON -> Pydantic 模型解析 -> 返回带类型的对象
```

## 核心组件

### 客户端 (MihomoAPI)

`MihomoAPI` 是库的入口类。常见用法：

```python
from mihomo import Language, MihomoAPI

client = MihomoAPI(language=Language.EN)
data = await client.fetch_user(800333171)
```

它提供异步方法（如 `fetch_user`）来拉取并解析玩家数据，并支持通过 `Language` 枚举切换语言。部分版本同时提供对应不同数据结构版本的拉取方法（例如 `fetch_user_v1`）。

### 数据模型 (models)

模型层使用 Pydantic 定义。由于 Mihomo API 存在多个数据结构版本，库通常提供对应的模型（例如默认结构与 V1 结构）。每个模型字段都带有类型标注，可直接通过属性访问。

### 工具函数 (tools)

工具层封装一些常用的数据处理逻辑，例如补全资源 URL、整理嵌套字段等。

### 错误处理 (errors)

库定义了若干异常类型，用于表示请求失败、用户不存在等情况。调用方可以捕获这些异常来做相应处理。

## 推荐的源码阅读顺序

1. 先看 `README.md`，了解库的定位与基本用法。
2. 阅读包的 `__init__.py`，弄清对外导出的公共接口。
3. 阅读客户端模块，理解请求是如何发出和解析的。
4. 阅读模型模块，对照 API 返回的 JSON 字段理解模型定义。
5. 最后阅读工具与错误模块，了解辅助逻辑与异常体系。

> 以上为帮助理解的总体框架，具体的模块划分与命名以仓库实际源码为准。

## 本地开发

1. 克隆仓库并创建虚拟环境。
2. 以可编辑模式安装：`pip install -e .`
3. 按照项目约定运行测试与静态检查。

## 贡献建议

- 保持改动聚焦，匹配现有代码风格。
- 修改模型时，确保字段与 API 实际返回保持一致。
- 提交前运行测试，避免破坏现有功能。
